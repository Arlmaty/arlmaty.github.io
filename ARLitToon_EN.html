Overview

Rather than physically-based realism, ARLitToon is optimized for illustration-like and cel-shaded expression. Particle color integration, dissolve, soft particles, HDR emission, and rim light are all built in as standard.

SEC. 02 — CORE

Transparency / Rendering

// transparency and rendering settings

Just choose from Preset according to your purpose, and the internal blend and Cutoff settings are optimized automatically. Basically you only need to choose a Preset; there is no need to touch the detailed settings below manually.

# Blend Preset

  • Opaque: Opaque (default). For ordinary bodies, clothes, weapons, etc. The lightest to process.
  • Cutout: For leaves, wire mesh, etc. Cuts out sharply using the texture's alpha.
  • Fade: For expressions where the whole object gradually becomes transparent, such as magic effects. Use this mode when you want to fade gradually by alpha value (fade in / out). ※ Optimized with the premultiplied (Premult) method so it does not blow out even under multiple lights.
  • Additive: For expressions that glow by adding color to the background, such as flames or glowing magic circles. Fading by alpha value is also possible.
  • Transparent: For glass, slime, etc. When you want transparency while keeping light reflections (highlights). Intended for expressing an always-semi-transparent "material quality", not for fading out gradually with alpha.

(※ With transparent-type presets, a safety process that prevents rendering errors on fully transparent parts is applied automatically.)

In other shaders, fading gradually by alpha is often possible with Transparent-type modes, but this shader's Transparent is optimized for always-semi-transparent material expressions such as glass. Even if you lower the material's transparency (_Color.a or the texture's alpha), highlights (specular reflection), environment reflections and emission remain without becoming transparent (to keep the material quality). Even if you animate _Color.a to 0, only the reflections, environment reflections and emission remain.
Therefore, if you want to fade the whole object in / out with the material's alpha or _Color's alpha, choose Fade (everything, including opaque emission and reflections, becomes transparent) or Additive.
[Exception: particle lifetime fade] Even with Transparent, when lowered by the alpha of the particle vertex color (Color over Lifetime), highlights, environment reflections and emission (including the Dissolve edge, Rim and Emission) all disappear completely. This distinguishes "material transparency = how see-through the glass is (reflections remain)" from "particle lifetime = existence itself (everything disappears when it disappears)". An effect that dissolves a Transparent glass material with Dissolve also works through this mechanism, disappearing naturally together with its reflections. Use it with Vertex Color Blend Mode set to Multiply.

Texture Layer

// 2nd-image overlay & alpha mask

A feature with two parts: a "color overlay" that puts another image on top of the base texture, and an "alpha mask" that cuts the base out to transparency using the image's brightness. The two are independent toggles; you can use either one or both together (they share the same Layer texture).

① Color Overlay (Use Texture Layer) — Useful for logos, embroidery, one-point patterns, tattoos, makeup, two-layer effect patterns, etc.

PropertyDescription

There is no need to prepare a separate mask image. Placement and repetition can be adjusted independently of the base with Tiling/Offset.
Color Tint (HDR)The tint applied to the layer image. Being HDR, it can be combined with Add/Screen for glowing overlays.
Blend ModeThe blend method. Normal (ordinary overlay) / Multiply (for shading and grime) / Add (glowing overlay) / Screen (brightening overlay).

② Alpha Mask (Use Texture Layer as Alpha Mask) — A feature that cuts out the base shape with a grayscale mask image.

PropertyDescription
Use Texture Layer as Alpha MaskEnable/disable the alpha mask.
Layer / Mask TextureSets the mask image (shared with the color overlay). The image's brightness becomes the transparency (black = transparent / white = opaque / gradient = semi-transparent). If you use only the mask with the color overlay OFF, opening this toggle shows the texture field.

Prepare a grayscale (black to white) mask image, drawing the parts you want to be see-through in black and the parts you want to keep in white. Intermediate colors and gradients become semi-transparent. When combined with the color overlay, the roles of the same image are divided: brightness = alpha mask / alpha = color blend mask.

The alpha mask is visible only with a transparent-type Blend Preset (Cutout / Fade / Transparent). With Opaque, opacity is ignored, so nothing becomes see-through. Cutout suits sharp cut-outs, and Fade suits smooth see-through with gradients. With Transparent, by design to keep the material's transparency, highlights such as reflections and emission remain and are not erased by the mask (for glass expressions).

The color overlay acts only on the object's color (look) and does not change opacity. Hue Shift acts only on the base color and does not affect this layer image (to keep the colors of logos, etc.). When disabled, the cost is almost zero.

# Dither Fade (dithered pseudo-transparency)

A feature that, while keeping Cutout / Opaque rendering, thins out pixels with a fine halftone (dither) pattern to create pseudo-transparency matching the alpha value. It is placed in this section because it is the same kind of "cut out with alpha" feature as the Alpha Mask above.

PropertyDescription
Dither FadeEnable/disable the feature (default OFF). When ON, the alpha value of the texture or layer mask becomes "the ratio of pixels kept" as is.

Transparent presets such as Fade cannot receive cast shadows (Receive Shadow) due to Unity's specification. For parts such as bangs that you "want semi-transparent but also want to receive shadows", use the Cutout preset + Dither Fade ON to make them see-through according to alpha while receiving shadows. Specification notes: Because the dots thin out pixels, a dotted pattern may be visible at very close range (less noticeable where anti-aliasing (MSAA) is enabled). Resolution, anti-aliasing and camera angle differ between the Scene view, the Game view and VRChat itself, so the appearance of the dots (how see-through it looks) changes. Check the final look in VRChat itself. Alpha Cutoff can be used together; alpha below Cutoff is still cut out completely. Alpha from Distance Fade and from the texture layer's alpha mask is also reflected as dots. This feature has no effect with transparent presets (Fade / Transparent / Additive), where ordinary alpha blending is used. Combined with Outline: When Outline's Alpha Sync is ON (default), the outline follows the same dots as the body (this prevents the outline color from showing through the holes as a saturated surface). Turning Alpha Sync OFF makes the outline ignore the dots and always be shown.

Whereas Texture Layer above "overlays only one image at runtime", this bakes everything into one image in advance, so there is no limit on the number of images and neither runtime cost nor texture memory increases (after baking, it remains a single texture).

Workflow

  1. Set the image you want to overlay in Texture Layer above, and decide its position (Tiling / Offset) and blend method (Blend Mode) by the actual look.
  2. Open Bake to Base and press Create Bake Recipe. If you want to stack even more images at once, register them with Add Layer.
  3. Pressing Preview (temporary bake) lets you check the bake result on the actual model. During preview, moving the bake settings (Base Color Adjust, each layer's adjustment, Opacity / Tiling / Offset, etc.) is reflected on the model in real time. The same applies when you change the Texture Layer settings above. It also follows Ctrl+Z (undo). Press End Preview to return to the original state.
  4. If everything looks fine, press Bake (create a new texture). The result is saved as a new PNG (<material name>_Baked.png) and the Albedo texture is replaced with it. A new file is created for each bake (_Baked 1.png → _Baked 2.png …), so previously baked textures are never overwritten. The save location is "the same folder as the source texture" (shown in Output folder of Bake to Base even before baking). When finished, a window showing the texture name and save path opens (you can select and copy the text, and Show in Project takes you to the asset). The baked Texture Layer is turned OFF automatically, and the captured color adjustment is merged into Base Color Adjust while the material side returns to its initial values (to avoid applying it twice).
  5. To stack more, set the next image in the freed Texture Layer and repeat steps 3-4.
  6. To start over, Revert to Source Texture returns to the state before any bake (source texture, HSV and Texture Layer ON/OFF). At that time, the steps added automatically by baking (the color adjustment and the captured Texture Layer) are also undone together (layers you added yourself remain).

Each bake is rebuilt from "source texture + bake steps", but what you baked remains as steps, so previously baked content does not disappear from the second time on. Because it is rebuilt from the original each time, image quality does not degrade no matter how many times you bake on top.

Base Color Adjust applies only to the source texture and a layer's adjustment only to that layer; they do not affect each other. To change only the color of a decal, move that layer's adjustment; to change only the underlying color, move Base Color Adjust. Neither accumulates (it is never applied twice however many times you re-bake). The adjustment captured by Also take the material's Color Adjust (HSV) applies only to the base color. If you move the material's sliders while layers already exist, the whole color changes on screen but only the base changes in the bake result; in that case a note is shown in the Inspector (use each layer's adjustment if you also want to change the layers' colors).

To check that the bake result was applied, look at Last result shown at the bottom of Bake to Base (e.g. Baked: base adjust yes / 2 layers (1 adjusted) (incl. Texture Layer)). If it says 0 layers, no image was baked that time (caused by Texture Layer being OFF, no texture set, etc.).

The bake result is saved as a new file each time (delete old bake results you no longer need from the Project window). Also, when a color adjustment (HSV) is baked, Hue / Saturation / Brightness automatically return to their initial values (0 / 1 / 1) so the same adjustment is not applied twice. These operations can be undone with Unity's Undo (Ctrl+Z).

However, the preview is uncompressed while compression settings apply after saving, so there may be a very slight difference in color. Do the final check after saving.

When the preview starts, the material's Hue / Saturation / Brightness temporarily return to their initial values (because they are included in the bake). Move these two sliders when you want to fine-tune colors (they are reflected in real time and baked with those values).

Baking is an operation in UV space. Elements that move over time cannot be baked (such as Texture Layer's Scroll). When Scroll is not 0, a note is shown and the picture in the stopped state (start position) is baked. Set Scroll to 0 and align the position with Tiling / Offset. Also, after baking, layers cannot be animated individually (scroll, fade, color change). If you have one image you want to move, use Texture Layer (runtime blending); bake designs that do not move. Note that when Color is tinted and a color adjustment (HSV) is baked, the color may change slightly before and after baking (at runtime Color is applied before HSV, while baking applies HSV to the image before Color). A note is shown in the Inspector when this condition applies. Check with the preview, or set Color to white before baking.

SEC. 06 — LIGHTING

PBR & Specular

// physically based texture, environment reflection, glass & metal mirroring

※ When Unlit Mode (ignore lighting) is ON, all other items in this section have no effect and are hidden from the Inspector (the Unlit Mode checkbox itself remains; the setting values are kept, and turning it OFF shows them again unchanged). The items of Lighting & Shadow, Toon Shadow and Back Light are hidden in the same way.

Both are pseudo effects decided only by the viewing direction, not by how light hits. Likewise Emission, Glitter, AudioLink, the Dissolve edge, Fake Shadow and Outline also work in Unlit. Only things that need real light sources and ambient light (shading, specular highlights, environment reflections, back light) do not work in Unlit.

This shader's lighting is physically based (PBR BRDF). The distinction between metal and non-metal is expressed with Metallic, and the calculation conserves the total amount of light. Toon shading (shadow color, border and blur in Lighting & Shadow) sits directly on top of it, so the cel-shaded look is kept.

PropertyDescription
Unlit ModeCompletely ignores light sources and always displays at 100% brightness. For particles and glowing effects.
MetallicWhether that surface is metal. The closer to 1, the more the paint color (diffuse light) disappears and the highlights and reflections are tinted with the base color (gold shines gold, copper shines copper-red). Metals such as gold, copper and brass are basically 1, and non-metals such as cloth, skin and plastic are 0; intermediate values are basically not used.
SmoothnessThe smoothness of the surface. It decides both how wide the highlight spreads and how blurry reflections are (high = sharp, small highlights + crisp reflections / low = broad, blurry reflections).
No shadow on metal (pure physical)At OFF (default), toon shading is also applied to metal reflections, so cast shadows and toon shadows also appear on metal parts. At ON, shading is not applied, giving the physically correct behavior, the same as a mirror showing the same scene even in shadow. In exchange, metal no longer shows shadows, and the higher the Smoothness, the less shading is visible. It does not affect surfaces with Metallic 0 (glass, cloth, skin).
Normal Map + ScaleUse it when you want to express fine bumps (wrinkles in clothes, grooves in bricks, etc.) without increasing the polygon count.

In the material of fittings or ornaments, set Metallic to 1 and Smoothness to 0.7-0.9 (Reflection Strength can stay at the default 1). Metal gets its color from the surrounding reflections, so it becomes dark if Reflection Strength is left at 0 (the Inspector shows a warning when Metallic is high but it is 0). Toon shading, outlines, Matcap and rim light can be used together as they are, so you can make only the fittings and ornaments look metallic while keeping the cel-shaded look. The shadows of metal can also be adjusted with Lighting & Shadow: since toon shading is also applied to reflections, Shadow Color / Shadow Border / Shadow Blur work on metal parts as they are (with high Smoothness the light-source highlight concentrates into a small point, but the shadow does not disappear because the reflection side expresses it).

A surface with raised Metallic loses its paint color (the diffuse light of the base color). This behavior follows the physical nature of metal. Raising Metallic on non-metal parts such as skin or cloth makes the color wash out and look dark. If you only want stronger shine (highlights), use Specular Highlight instead of Metallic.

# Specular Reflection (environment reflection / reflections on glass and metal)

PropertyDescription

Note that when Transparent glass is used in particles and faded out with Color over Lifetime, everything, including environment reflections, Matcap and emission, disappears completely. The calculation is also skipped, so there is no cost.

What gets reflected depends on the VRChat world's reflection probes / skybox. In worlds without probes, reflections may become dark (like soft particles and AudioLink, this is a specification constraint that depends on the world environment).

The shadow in this section decides its direction by mixing the real light's direction with the direction of a "pseudo light" decided from the distribution of surrounding brightness (Pseudo Light, default 0.5 = half and half). Only the toon shading of this section switches to the pseudo light.

Shadows overlap from the outside in the order 1st shadow → 2nd shadow → 3rd shadow. For an anime look, lower each Blur to make boundaries clear; raise them for a softer look.

Setting it to 0 removes the shadow regardless of the number of tiers.

While Shadow Flat Mode is ON, each shadow's Normal Strength has no effect on the shadow (because normals are no longer referenced). The normal map itself still works on highlights and reflections as before.

Shadows are received only when the world has a realtime directional light, its shadows are enabled, and you are within the shadow draw distance. In worlds that do not meet these conditions, the display is as before (the same look as OFF). The avatar's ability to "cast" shadows has always been enabled; this setting only concerns the "receiving" side.

# Light Limit (ambient clamp / prevents blow-out and crushed blacks)

When the world's ambient light is excessively bright or dark, it limits the amount of light the avatar receives to a fixed range, preventing blow-out or situations where nothing can be seen in the dark. It is darker in dark worlds, and in bright worlds it leaves some headroom for brightness within a range that does not blow out.

PropertyDescription
Light Min LimitThe lower bound of the light that part receives. In shadows or dark worlds, the shortfall below the lower bound is supplemented as flat ambient light. The higher it is, the more the shadows are lifted and brightened; the lower, the deeper the shadows sink (0 = no lower bound = shadows can be completely dark).
Light Max LimitThe upper bound of brightness in bright places (prevents blow-out). The higher it is, the brighter it looks in bright worlds.

The lower bound works on the amount of light received per pixel, so it can lift only the shaded parts while leaving lit surfaces as they are. Raise it when facial shading is crushed and invisible in dark worlds, or when you want to keep shadows light. To change the shadow color itself, use Shadow Color / Shadow Intensity in Lighting & Shadow (these specify the color and depth of the shadow directly rather than the amount of light).

This feature is always enabled. It works only in Lit (Unlit OFF); in Unlit mode it does not respond to light, so this item itself is hidden automatically. Emission and environment reflections are not subject to the limit. Additional realtime lights also go through one combined upper/lower bound process together with the main light and ambient light (additional lights are treated per vertex, up to 4 lights). _LightMinLimit / _LightMaxLimit are animatable.

In worlds dominated by ambient light (light probes) and in back-lit scenes, it automatically restores the lit / shaded side from the directional information contained in the ambient light, reducing the look of the body sinking flat with uniform brightness. A little ambient light from behind wraps around to the outline (silhouette) side, keeping volume even when back-lit. There are no settings; it always runs with the optimal settings (the change is slight in worlds with a strong directional light).

// backlight that glows only when the light is behind

This shadow is drawn by shifting the mesh along the light direction, so the outline of the shadow on screen is "the silhouette of the casting side seen from the camera". The blur is created by making that boundary — where the surface turns sideways — lighter. Therefore it blurs well on hair with thick strands (tube-shaped meshes), but on bangs made of flat cards, the direction is constant within each card's surface, so even the edges never "turn sideways" and there is almost no change. In that case use Cast Shadow Depth Fade (unaffected by shape), or combine both.

The shape of the shadow is the shape of the mesh itself (the shape of the bangs becomes the shadow as is). Since the receiver is curved, the larger the cast distance, the more the shadow appears detached from the receiver. In VR the look differs between the two eyes, so decide the distance while actually checking in VR. The shadow does not darken emissive effects (Emission, Rim Light, Glitter, etc.). When disabled, no drawing happens at all, so the cost is almost zero.

# Fake Shadow Texture (receiving side / designed cast shadow, shadow of the bangs)

A feature that shows a "shadow drawn by the author", such as the shadow of bangs, on the object always at the same position and strength regardless of the world's light sources. Use it when you want to show the shading intended as part of the illustration's painting without it breaking in any world.

Conversely, when using it for multiple features, always separate the channels — a grayscale image puts the same picture into all channels, so as it is, Matcap's region mask and the shadow would have the same shape.

Fake Shadow Texture uses this Shared Mask, so Texture Layer's color overlay and alpha mask can still be used freely as before (they can be used at the same time).

It is a still image drawn in UV space, not geometric self-shadowing. Therefore it does not follow head movement or the light direction (the purpose of the feature is to always show the same design). The shadow is applied to the object's color, so it appears the same way in Unlit mode and in dark worlds, but it does not darken emissive effects such as Emission, Rim Light and Glitter (the shadow is hard to see on glowing parts). Scrolling (flowing movement) is not applied. When disabled, the cost is almost zero.

Outline & Sweep

// outline & orbiting-glow option

The base feature that draws the outline of a mesh. It supports everything from toon-style edging to glowing outlines like neon tubes with HDR color + Bloom. It works with any 3D mesh, such as spheres, cubes, text, costumes and accessories, and follows animation on skinned meshes. The basic outline can be drawn without textures or UV unwrapping (a mask is optional: use a mask image only when you want to remove the line partially, such as at the outer corners of the eyes).

PropertyDescription
Use OutlineEnable/disable the feature.
Base Color (HDR)The color of the outline. Being HDR, raising Intensity makes Bloom (light bleeding) work nicely. A (alpha) is the opacity of the outline itself (effective since v34, default 1 = opaque).
Self-IlluminateThe degree to which the outline ignores the world's lighting and self-emits (0-1, default 0). At 0 (default), the outline follows the scene's brightness uniformly (the total of the main Directional Light + ambient light, following Light Min/Max Limit) (bright (white) when there is a Directional Light, gray to black only when the whole scene is dark; the line is uniform with no light/dark boundary; in complete darkness it stops at Light Min Limit and turns off at 0). At 1 it ignores lighting and always glows (the classic neon). Adjust the glow strength with the brightness of Base Color (HDR). Animatable. ※ This value affects how the following Intensity / Line Width work (the brightness reference), so it is placed right after Base Color so it can be decided first.
IntensityThe glow strength of the line (0-16).
Line WidthThe thickness of the outline (the amount the mesh is pushed out). The slider is 0-20 (in 0.01 steps, two decimal places), and at 0 the line disappears. The range is for fine-tuning thin lines (the displayed value is a convenient multiple of the internal value; the meaning of the effect and saved value depends only on its magnitude).
Extrude ModeNormal = along the normal (for beveled text, meshes with multiple parts such as strings of text, and smooth general models) / PivotScale = outward from the pivot (for hard-edged single convex shapes such as cubes; corners do not split).
Alpha Sync (follow material alpha)With transparent presets (Transparent / Fade / Additive), makes the outline follow the body's transparency (Color A × main texture A) (default ON). The more see-through the body, the fainter the outline color seen through the body becomes, and no line appears on fully transparent parts (no depth is written either). OFF = always shown regardless of transparency as before (the previous look where the outline color shows through on the inside). With opaque (Opaque / Cutout) presets the body is not see-through, so it has no effect.
Use Outline Mask (hide line partially)A feature to partially remove the outline with a texture mask (default OFF). You can remove only the places where you do not want a line, such as the outer corners of the eyes or around the mouth. When ON, the mask field below is shown.
Outline MaskA grayscale mask image. White = line / black = no line (gradient in between). It is read with the same UV as the main texture. Parts removed by the mask do not write depth, so see-through of the back side does not increase when transparent.

When you enable Outline, it starts with easy-to-use initial settings (Intensity 1 / Line Width 0.1 / Sweep OFF). The values can be changed freely afterwards. Note that if you turn Outline OFF once and enable it again, it returns to these initial settings.

The outline is drawn geometrically with the method of "drawing only the back faces of a slightly inflated copy of the mesh" (inverted hull). Therefore the outline appears accurately even on flat meshes such as cubes.

  • Normal: pushes out along the normals, so the line thickness is uniform. The line may break at hard-edged (flat-shaded) corners. In that case switch to PivotScale, or give the model bevels / smooth normals.
  • PivotScale: pushes out radially from the pivot, so corners do not split, but the line thickness becomes uneven on meshes with multiple parts such as strings of text, and on concave shapes (no line appears on the side facing the pivot). Consider it dedicated to single convex shapes.
  • The outline follows the bone deformation of skinned meshes. Use Normal for Extrude Mode (PivotScale breaks on full-body meshes).
  • The line thickness is proportional to the avatar's scale (the visual ratio is kept even on huge or tiny avatars).
  • For parts where you do not want an outline, such as the face, turn Outline OFF on that material (or set Line Width to 0). Avatars usually have separate materials per part, so this is the basic means of per-part control. If you want to remove only part of it within one material, such as the outer corners of the eyes, use Use Outline Mask (white = line / black = no line).
  • The vertex processing of that material roughly doubles, plus one more draw call. It is within a practical range even for a full body, but if you care about Performance Rank, narrow down where it is applied.

# Sweep (orbiting glow option)

An option where an especially bright streak of light orbits around the outline of Outline. Useful for "running light" effects on neon tubes, cyber gadgets, magic circles, etc. It works only when Outline is enabled.

PropertyDescription
Use SweepEnable/disable the option.
Base Glow (base tube brightness / contrast with streak)The base brightness of the outline (tube) = the foundation on which the orbiting streak runs (0-1, default 0.3). Lowering it creates the contrast of "a strong streak of light running over a faintly glowing tube". Since v34, the streak's brightness is capped at the same brightness as the solid line with Sweep OFF, so Sweep no longer saturates (blows out) the outline. Therefore at 1 the tube and streak have the same brightness and the streak becomes invisible (when you enable Sweep in the GUI and it is near 1, it is automatically corrected to 0.3). A Sweep-only setting (shown when Sweep is enabled). When Sweep is OFF, Base Glow has no effect and the outline becomes a uniform solid line (adjust the brightness with Intensity and Base Color).
Width (streak length)The total length of the streak of light. The smaller, the more point-like; the larger, the longer it glows.
Sharpness (falloff sharpness / symmetric)The sharpness of the falloff applied symmetrically to both sides from the center of the streak. The larger, the sharper the center stands out; the smaller, the more gently the whole thing glows.
Speed (orbit speed / sign reverses)The orbiting speed. The sign reverses the orbit direction (positive = one direction / negative = the opposite). 0 stops it. Animatable, and the number shown in the Inspector is used directly as the animation value.
Count (number of streaks)The number of streaks orbiting at the same time (an integer from 1 to 8). At 2 or more, multiple evenly spaced lights chase each other.
Pivot Offset (orbit center / object space)The offset of the center the streak orbits around (object space). Normally it can stay at (0,0,0). When used on an avatar body, set Y to chest height (e.g. 1.0) to make the orbit even.
Edge Fade (suppress radial bleed when transparent / 0 = off)When Sweep shows through radially behind the body with transparency (Transparent / Fade), it keeps the rim streak and suppresses only the inner radial part (0-8, default 2). 0 = disabled. A feature for smooth curved surfaces (spheres, organic meshes). When opaque, the back side is hidden by the body, so it has no effect. ⚠️ On hard-edged meshes (cubes, etc.) the rim streak is also attenuated, so set it to 0 in that case (the outline itself is not affected by Edge Fade and is always shown).

The position of the streak is generated from the angle on screen as seen from the camera, so from whatever direction you look, the streak goes around the outline currently visible. Because it is a view-based (viewer-side) effect, tilting your head (camera) also rotates the starting point of the orbit together with the screen. In VRChat mirrors the orbit direction appears reversed; this is a specification common to viewpoint-dependent effects such as Matcap.

  • When using this material on particles, the outline is drawn for each particle, so OFF is recommended for particle use (when ON, the line follows the lifetime fade).
  • This feature does not use shader keywords, so enabling it does not increase the compile time at upload (number of variants). When OFF the rendering cost is almost zero, but there is one more draw call for the dedicated pass.
  • With Transparent / Fade presets, when the body becomes semi-transparent, the back side (the inner wall of the outline color) may show through the body. Since v34, Alpha Sync (default ON) makes the outline color seen through follow the body's transparency and fade together (if the body is fully transparent, the line disappears too). Turning Alpha Sync OFF shows it always regardless of transparency as before (it is drawn geometrically, so it never disappears on any mesh). If radial see-through of Sweep bothers you, on smooth curved surfaces Sweep's Edge Fade (default 2) suppresses the inner radial part (0 recommended for hard-edged meshes).

Glitter / Sparkle (procedural glitter)

// procedural glitter

A decorative emission layer that scatters fine sparkling grains (glitter / sparkle) over the surface without using textures. The grains are generated procedurally in the shader, so no dedicated noise image is needed. The grains glint as you move your view (an expression that twinkles with the viewing angle, like metallic glitter or flakes). It works as an additive layer independent of normal Emission (constant glow), so even with Emission OFF, Glitter alone can glow.

PropertyDescription
Use GlitterEnable/disable the feature. When turned ON, Intensity is automatically set to 1 (kept if it already has a value).
Glitter Color (HDR)The emission color of the glitter (HDR). Raising Intensity affects Bloom.
IntensityThe glow strength (0-16).
ShapeChooses the grain shape from Point (round dot) / Star (a cross-shaped glint with sharp tips) / Diamond / Fine Dust (dense fine glitter). The outline is kept sharp at any size (it does not blur when enlarged).
SpaceChooses the base coordinates of the grains from UV (follows the mesh's UVs; natural scrolling; for flat surfaces / particles) / Object (object space; uniform without stretching even on cube sides or sphere poles thanks to triplanar projection) / View (a "billboard" expression where grains always face the camera, based on world coordinates; completely unaffected by the mesh's UV unwrap and by front/back faces).
Grain ScaleThe size of one grain. The larger the value, the larger the grains; the smaller, the finer (default 181). Making grains smaller automatically increases their number, so density does not fall short even with fine glitter. Raise the value for large glitter (around 290 gives coarse glitter).
CoverageThe ratio of grains that actually glow. Closer to 0 is sparse; closer to 1 glows densely (default 0.6).
Grain SizeThe fill ratio of one grain (how large it is drawn within its cell, default 0.7). Because it is independent of density, grains do not get clipped even if you raise density while keeping them large (the absolute grain size is adjusted with Grain Scale).
View SharpnessThe sharpness of the glint relative to the line of sight. The larger the value, the more sharply and briefly it flashes at specific angles.
Flicker SpeedThe speed of flickering (0 = no flicker). Flickering is random per grain, and speed and timing differ grain by grain. Furthermore, two waves with different periods are overlaid, so a pattern where the same flicker repeats at the same place is practically imperceptible.
Scroll (X,Y)The speed that moves grains as if flowing (translates the UV / Object coordinates respectively). The input fields are X/Y only (Z/W are unused).
AudioLink ReactiveWhen ON, the glitter flicker is driven by sound (AudioLink). Adjust with Band (the frequency range to react to) and Sound Strength (how much the sound affects it).
Localize with Emission MapWhen ON, limits where glitter appears with the Emission Map. The map is shared with Emission (the whole surface if not set).
Mask ChannelChooses the channel of the Emission Map used for localization. Brightness (RGB) (default) = the brightness of the emission picture (white = appears / black = does not). It is read with the same UV as the emission, so it moves with Emission's Tiling and scrolling. Alpha (A) = the alpha of the Emission Map (opaque = appears / transparent = does not). It is read with the same UV as the main texture and is not affected by Emission's Tiling or scrolling. It can be drawn separately from the emission color (RGB), so you can place glitter even where nothing glows. The alpha is shared with the Emission / AudioLink masks (see "About the Emission Map alpha" in the Emission section).

Glitter is an additive emission layer calculated as Glitter Color × Intensity × (shape × view glint × flicker × (AudioLink) × mask). Being procedurally generated without textures, it adds no samplers or keywords (compile load at upload stays the same). The glow follows transparency and blends naturally with particle lifetime fades and semi-transparency. Glitter Color / Intensity / Flicker Speed and others can also be animated.

① An image without alpha (JPG or PNG without alpha) is read with alpha 1 everywhere, so glitter appears over the whole surface. ② Set Alpha Is Transparency to OFF in the Emission Map's import settings. When ON, Unity fills the color of transparent parts with surrounding colors on import, so the emission color may change where no glitter is placed. The Inspector warns about both of these states.

Like the other sound-reactive features, AudioLink Reactive works only when the AudioLink system is installed in the VRChat world (in unsupported worlds only the sound linkage of the flicker is disabled automatically; the glitter itself is shown normally). The Object space is based on object space, so the grains stay fixed to the surface and follow even when the avatar moves or rotates (UV depends on the mesh's UV unwrap, so grains also stretch where UVs are stretched). On double-sided (Cull Off) meshes, grains on the back also glow correctly.

The grains stay tied to world coordinates while always facing the camera, so the mesh's UV unwrap, surface orientation and front/back are not considered at all. Like Object, it is composited with triplanar projection, so grains are not stretched even on surfaces seen at an angle. Grain shape and size stay uniform even on meshes without UVs, places where UVs are heavily distorted, and double-sided polygons. It is also not affected by the object's scale, so grain size stays consistent across multiple meshes. In VR, grains do not shift between the left and right eyes. Note that rotating the camera rearranges the grains (a specification of the always-facing-front expression).

AudioLink (music-reactive emission)

// music-reactive glow

A feature that makes things glow along with the music playing in the world. A standard feature in VRChat club worlds and live performances.

This shader's AudioLink works as a "sound-reactive emission layer" independent of normal Emission (constant glow). It adds emission toward the base (color × Intensity) according to the loudness of the sound, so even with normal Emission OFF, AudioLink alone can glow along with the sound. Conversely, with normal Emission ON, the sound-reactive glow is layered on top of the constant glow (they do not cancel each other out).

PropertyDescription
Use AudioLinkEnable/disable the feature. When turned ON, the reaction amount and Intensity are automatically set to 1, ready to react immediately (kept if they already have values).
AudioLink BandChooses the frequency range to react to from Bass / LowMid / HighMid / Treble. Bass reacts to kicks, treble to hi-hats and the like.
Emission Reaction (Master)How much it follows the sound. 0 = no reaction, 1 = fully linked to the volume (the AudioLink glow disappears when silent). _AudioLinkEmission is animatable.
AudioLink Emission Color (HDR)The color that glows with the sound reaction (HDR). It can be specified separately from normal Emission.
AudioLink Emission IntensityThe strength of the sound-reactive glow. The upper limit of brightness reached at the peak of the sound (0-16).
Mask with Emission Map alphaWhen ON, limits the area of the sound-reactive glow with the alpha of the Emission Map (opaque = glows / transparent = does not glow). Using with Particles (Particle System)

This shader is designed with use in particle effects in mind.

  1. Set this material in the Particle System's Renderer > Material
  2. Change the material's Vertex Color Blend Mode to Multiply

That is all it takes. No additional settings such as checking Enable Mesh GPU Instancing or Custom Vertex Streams are needed.

Performance & Optimization

This shader is maximally optimized for lightweight operation and compile speed in the VRChat environment.

  • Drawing passes not used for avatar purposes (ShadowCaster, Deferred passes) and internal variants for fog/lightmaps are completely purged, greatly shortening build (upload) time.

About VRChat Fallback

The shader has the "VRCFallback" = "Standard" tag set.

Even if a custom shader is disabled by another user's Safety settings within VRChat, it is automatically replaced with Unity's built-in Standard shader, preventing the avatar from turning pink (material error).
